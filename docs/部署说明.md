# 部署说明

## 1 环境要求

- Cocos Creator 3.8.x
- Node.js 24 推荐版本，仅用于命令行校验和测试
- 微信开发者工具，仅在构建微信小游戏时需要

工程不依赖第三方运行时包，关卡和碰撞逻辑均由项目内 TypeScript 实现。

## 2 首次打开

1. 在 Cocos Dashboard 中导入本项目根目录 `D:\job\software engineering`。
2. 使用 Cocos Creator 3.8.x 打开，等待编辑器生成 `library`、`temp` 和资源 `.meta` 文件。
3. 新建或打开主场景，创建 `Canvas`。
4. 在 `Canvas` 下创建空节点 `GameRoot`。
5. 给 `GameRoot` 添加 `GameManager` 组件。
6. 可选的 `livesLabel`、`levelLabel` 和按钮按模块开发文档绑定。
7. 保存场景并加入构建场景列表。

`GameManager` 在启动时会自动添加 `UIManager` 并加载已解锁的最高关卡。`BoardRoot` 未手动指定时，也会自动创建。

## 3 本地预览

在 Cocos Creator 中点击预览。验证以下流程：

- 普通箭头按显示方向移动。
- 反转箭头使用显示方向的反方向。
- 固定箭头点击后只执行受阻动画。
- 墙体和其他箭头能够阻挡路径。
- 全部可移动箭头消失后显示通关星级。
- 生命耗尽后显示失败提示。
- 重置恢复初始棋盘，提示高亮可释放箭头。

## 4 命令行校验

在项目根目录执行：

```powershell
npm run validate:levels
npm run test:domain
git diff --check
```

领域测试覆盖箭头多态、路径阻挡、三个关卡的可解性以及最高星级持久化。

## 5 微信小游戏构建

1. 在 Cocos Creator 的“项目”设置中填写微信小游戏 AppID。
2. 打开“构建发布”，选择微信小游戏。
3. 设置输出目录，例如 `build/wechatgame`。
4. 选择主场景并执行构建。
5. 用微信开发者工具导入输出目录，完成真机或模拟器调试。

存档键为 `arrow-game-save`。微信环境优先调用 `wx.setStorageSync` 和 `wx.getStorageSync`，其他环境使用 Cocos `sys.localStorage`。

## 6 常见问题

**资源加载失败**

检查关卡清单是否位于 `assets/resources/levels/level-manifest.json`，以及 `resource` 字段是否省略 `.json` 后缀。

**关卡被判定为锁定**

检查存档中的 `maxUnlockedOrder` 和关卡的 `order`。测试时可清除 `arrow-game-save` 后重新开始。

**点击箭头没有反应**

确认 `GameRoot` 位于 `Canvas` 下，节点具有 `UITransform`，并且所有 UI 输入没有被上层节点拦截。

**箭头显示但无法渲染**

确认主场景包含正常的 UI 相机和 Canvas，脚本位于 `assets/scripts`，且 Cocos 已完成 TypeScript 编译。

## 7 发布检查

- 构建场景列表只包含正式主场景。
- 微信 AppID 和服务器域名配置正确。
- 关卡 JSON 已通过 `npm run validate:levels`。
- 领域测试全部通过。
- 不提交 `build`、`library`、`temp`、`local` 目录。
- 合并到 `main` 后再打发布标签或创建版本。
