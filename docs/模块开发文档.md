# 模块开发文档

## 1 工程结构

```text
assets/
  resources/levels/          可序列化关卡清单与关卡 JSON
  scripts/
    app/GameManager.ts       应用入口、生命、胜负和流程调度
    managers/
      LevelManager.ts        关卡加载、实例化、提示、解锁和结算
      UIManager.ts           棋盘绘制、点击、动画和提示
    core/
      ArrowBase.ts           箭头抽象基类
      arrows/                普通、固定、反转箭头
      Block.ts               墙体
      CollisionDetector.ts   路径阻挡检测
      Direction.ts           方向与反向计算
      GridPoint.ts           网格坐标
      GameTypes.ts           通用状态和结果类型
    levels/LevelConfig.ts    JSON 解析、默认值与完整性校验
    storage/
      SaveData.ts            存档接口
      StorageManager.ts      进度、星级和设置读写
      CocosLocalStorage.ts   Cocos/微信平台存储适配
    utils/JsonResourceLoader.ts
docs/                        开发、部署和课程设计文档
scripts/validate-levels.ts   命令行关卡校验
tests/domain.test.ts         无引擎依赖的领域测试
```

## 2 运行时流程

1. `GameManager` 创建存储和关卡管理器。
2. `LevelManager` 加载 `levels/level-manifest`。
3. 选择当前已解锁的最高关卡，并通过 `resources.load` 读取 JSON。
4. `LevelConfigParser` 校验尺寸、方向、对象 ID、重叠和身体连续性。
5. `LevelManager` 创建箭头和墙体模型。
6. `UIManager` 根据模型绘制网格、墙体和箭头。
7. 点击后由 `CollisionDetector` 检查箭头头部到边界之间的格子。
8. 路径畅通时播放滑出动画并从关卡中删除；受阻时播放退回并扣除生命。
9. 清除所有可移动箭头后结算星级、保存进度并解锁下一关。

## 3 核心类职责

`GameManager` 是唯一的全局流程入口。它不实现碰撞、资源读取或持久化算法，只协调管理器并处理生命、失败、胜利和星级计算。

`LevelManager` 负责把配置转换为运行时对象。新增关卡时只修改 JSON，不需要在逻辑里增加关卡分支。

`ArrowBase` 保存箭头头部、身体折线、显示方向和绘制顺序。实际移动方向由抽象方法 `getMoveDirection()` 决定：

- `NormalArrow` 返回显示方向。
- `ReverseArrow` 返回显示方向的反方向。
- `FixedArrow` 返回 `null`，不参与可清除数量统计。

`CollisionDetector` 为无状态静态工具。它从箭头头部的下一个格子开始，沿实际移动方向逐格检查，遇到其他箭头或墙体即判定受阻，当前箭头自身被排除。

`UIManager` 只负责把模型转换为节点和动画。箭头节点保存显示位置，模型保存逻辑格子；两者不能互相替代。

`StorageManager` 面向可序列化 JSON。Cocos 微信小游戏优先使用 `wx` 同步存储，其他平台回退到 `sys.localStorage`。

## 4 关卡配置

关卡清单位于 `assets/resources/levels/level-manifest.json`。每个资源路径不带 `.json` 后缀。

```json
{
  "levelId": "level-004",
  "order": 4,
  "name": "新关卡",
  "resource": "levels/level-004"
}
```

单关配置的主要字段如下：

| 字段 | 说明 |
| --- | --- |
| `rows`、`columns` | 网格行列数，从 1 开始 |
| `cellSize` | 表现层单格像素大小，不参与碰撞 |
| `initialLives` | 初始生命 |
| `blockedTapCostsLife` | 受阻点击是否扣血 |
| `starRules` | 二星、三星允许的错误次数和提示次数 |
| `arrows` | 箭头配置数组 |
| `walls` | 墙体配置数组 |

箭头 `body` 的第一个坐标是蛇头，后续坐标必须沿上下左右相邻。箭头和墙体不能重叠，所有坐标必须位于棋盘内部。

## 5 关卡与星级

关卡是否解锁由 `order` 和存档中的 `maxUnlockedOrder` 共同判断。通关当前关卡后，系统记录完成状态、完成时间和历史最高星级，并解锁顺序上的下一关。

星级只升不降：

- 在三星阈值内完成，保存三星。
- 未达到三星但达到二星阈值，保存二星。
- 其余情况至少保存一星。
- 重玩低星级成绩不会覆盖历史最高星级。

## 6 界面绑定

将 `GameManager` 挂到常驻根节点的 `GameRoot`。同节点会自动添加 `UIManager`，也可以手动挂载后拖到 `GameManager.uiManager`。

`UIManager` 会创建以下绘制节点，也可在编辑器中指定：

- `BoardRoot`：棋盘、墙体和箭头。
- `EffectsRoot`：提示和通关文字。
- `livesLabel`、`levelLabel`：可选的 HUD 标签。

重置、提示和下一关按钮可绑定到 `UIManager.triggerReset()`、`triggerHint()` 和 `triggerNextLevel()`。

## 7 扩展方向

新增箭头类型时，应继承 `ArrowBase` 并实现 `getMoveDirection()`，再在 `LevelConfigParser` 中扩展合法类型，在 `LevelManager.createArrow()` 中注册构造分支。

新增公共字段时先修改 `LevelConfig` 和解析器，再更新关卡文件。不要在业务代码里读取原始 `unknown` JSON。

如果需要音效，应新增独立的 `AudioManager`，由 `GameManager` 调用；不要把手势、音频和碰撞逻辑塞进 `ArrowBase`。
