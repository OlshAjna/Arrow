# 代码规范

## 1 分层

- `core`：纯 TypeScript 玩法、几何和碰撞，禁止导入 `cc` 或 UI。
- `app`：对局入口和全局状态，不直接绘制节点。
- `managers`：关卡资源、进度和解锁。
- `storage`：存档模型与平台适配。
- `GameView`：Cocos 节点、输入、动画和 HUD。

依赖方向从表现层流向应用层，再到核心逻辑。核心逻辑不得依赖具体场景。

## 2 命名

- 类、接口和类型使用 `PascalCase`。
- 方法、字段和变量使用 `camelCase`。
- 常量使用描述性大写名称。
- 关卡 ID 使用稳定字符串，不使用数组下标或节点名称。

## 3 类型与数据

- TypeScript 开启严格检查。
- 外部 JSON 先通过校验函数处理，业务层只接收 `LevelConfig`。
- 逻辑坐标使用左上角原点和 `y` 向下，Cocos 节点坐标只在表现层转换。
- 存档只保存 JSON 数据，不保存 `Node`、`Graphics`、动画或类实例。
- 新增可配置字段时先修改数据模型和校验，再修改关卡 JSON。

## 4 状态与动画

- `checkMove` 必须保持只读。
- 动画结束后才能执行 `commitClear` 或 `registerBlocked`。
- 动画期间忽略重复点击。
- 受阻退回只改变显示偏移，不修改逻辑坐标。
- 长折线飞出不能直接整体平移，应沿路径裁剪。

## 5 错误处理

- 关卡 ID、尺寸、重复 ID 和碰撞盒错误在加载时抛出。
- 存储损坏时返回默认存档。
- 资源加载失败显示为界面消息，不静默进入空棋盘。

## 6 提交检查

```powershell
pnpm typecheck
pnpm validate:levels
pnpm test:domain
git diff --check
```

涉及 Cocos 场景的修改还应在 Cocos Creator 3.8.6 中预览确认。
