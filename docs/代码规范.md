# 代码规范

## 1 分层约束

工程按职责分为四层：

- `assets/scripts/app`：应用入口和全局流程，只放 `GameManager`。
- `assets/scripts/managers`：关卡、界面等业务协调者。
- `assets/scripts/core`：不依赖 Cocos 的箭头、墙体和碰撞规则。
- `assets/scripts/storage`、`assets/scripts/utils`：基础设施适配。

依赖方向必须从上层指向下层。`core` 不允许导入 `cc`、`GameManager` 或 `UIManager`，确保碰撞和箭头规则可以脱离引擎测试。

## 2 命名与文件

- TypeScript 类和接口使用 `PascalCase`。
- 方法和变量使用 `camelCase`。
- 普通常量使用 `UPPER_SNAKE_CASE` 或描述性的 `camelCase`。
- 每个公开类型单独成文件，文件名与主要导出类型保持一致。
- 一个文件只承担一个明确职责；管理器可以协调多个核心类，但不能直接绘制节点。

## 3 TypeScript 约定

- 开启 `strict`，避免隐式 `any`。
- 数据和 API 使用明确接口；外部 JSON 先按 `unknown` 接收，再由解析器校验。
- 不把 `int`、`bool` 等 UML 简写直接写进实现，统一使用 `number`、`boolean`。
- Cocos 只允许出现在组件和平台适配文件中。
- 可序列化关卡数据不得引用类实例、`Map`、`Set` 或节点。

## 4 错误处理

- 关卡资源、字段和对象重叠错误由 `LevelConfigParser` 抛出带路径的异常。
- 资源加载错误由 `LevelManager` 向上传递，最终由 `GameManager` 转成界面提示。
- 缓存损坏或存档字段缺失时，`StorageManager` 使用默认值恢复，不直接删除玩家数据。
- 异步动画期间由 `GameManager.busy` 锁定流程，禁止重复点击。

## 5 变更检查

提交前至少执行：

```powershell
npm run validate:levels
npm run test:domain
git diff --check
```

涉及 Cocos API 或界面绑定的修改，还应在 Cocos Creator 中运行预览，并验证普通箭头、反转箭头、固定障碍、受阻回退、胜利和失败流程。

## 6 Git 约定

- `main` 保持可运行。
- 功能开发使用 `feature/<名称>` 分支。
- 提交信息采用 `type: summary`，例如 `feat: add level unlocking`、`fix: preserve best stars`。
- 合并前先完成测试和 Cocos 预览，再使用普通合并或 `--no-ff` 合并回 `main`。
